    off = free-run

    update_interval: 1s (dbk.yaml:730) — the writer runs once a second and there is no other update trigger, so the panel only ever renders whole-second frames. With 1 Hz on, play steps millis in exact 1000 ms increments, which is why the splash bar jumps 0 → 32 → 64 px and never reaches 95: that is the real hardware behaviour. Free-run sweeps all 96 widths — smoother, but it shows frames the panel cannot produce.

    PMSx003 sensor

    Values print as %.0f. font_value only has 0-9 and space — anything else (a -, a ., or the n a n of a stateless sensor) renders as the firmware's hollow "missing glyph" box, exactly as the panel would.

    The lambda gates only on pms_pm25.has_state() (dbk.yaml:794) but then reads pms_pm1.state and pms_pm10.state unconditionally (:806, :808). An ESPHome Sensor with no state holds NAN, so those two boxes reproduce the real nan → three hollow boxes output that the PM2.5 switch can never reach (it takes the SENSOR ERROR branch instead).
